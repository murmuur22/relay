# Local streaming experiment

Evidence: [raw measured results](benchmark-results.json), generated by `npm run benchmark`. These measurements are a development baseline, not promised requirements for a Debian VM.

## Environment and workload

- Apple M1 Pro, darwin/arm64, 8 logical CPUs, OS-reported memory17179869184 bytes.
- Node v26.8.1, Playwright1.63.0, Chromium153.0.8010.12.
- One sandbox-enabled server-side Chromium, separate contexts for two synthetic pages.
- Each viewport1280×720. Counters change every100ms; this is not a scrolling/video stress workload.
- CDP JPEG quality65 over WebSocket JSON/base64, not WebRTC or a verified hardware video encoder.
- Observation60.003 seconds after warm-up. This is not the requested hour-long production stability test.

## Observed baseline

- Notes Lab:9.98 frames/s,2.16Mbit/s application JSON payload.
- Signal Lab:9.97 frames/s,2.13Mbit/s application JSON payload.
- Stream-browser reported RSS sum:355.3MiB; average CPU consumption0.224 logical cores.
- Gateway/benchmark Node process:206.5MiB RSS; average0.047 cores.
- Send-to-client-decode/draw age:p956ms for each stream **on this same Mac**.
- Signal minimized:zero frames during the measured three-second interval, while Notes continued.
- Twenty open/close cycles completed; only the intentionally retained Notes context remained.

The observed frame rate follows the test page's approximately10Hz updates. It neither proves a15–30fps interactive target nor establishes a10fps maximum. JSON byte counts exclude TCP/TLS/Tailscale overhead; this is not measured home uplink usage. CPU comes from measured CPU-time deltas over the observation interval. Browser memory is summed process RSS, not deduplicated physical memory. The gateway number includes the benchmark harness. Native Keepsakes/Python and the local full Svelte browser client's costs are not included in those figures.

## Not measured yet

True input-to-visible-response latency, WAN/50–100ms RTT behavior, static settled bandwidth, realistic scrolling workloads, Debian resource constraints, Safari, mobile hardware, hour-long stability or GPU encoder use. WebSocket ping and the6ms send-to-decode figure must not be presented as input latency.

## Decision

Keep the CDP image adapter for the local prototype: simultaneous capture and independent pause work, and local resource use is modest for this synthetic workload. Keep Svelte for the shell; its local drag/resize does not require a streaming round trip. Do not introduce WebRTC, alternative frontend frameworks or a browser-per-app process model without a measured reason.

Before production: repeat on the intended Debian VM with real approved services, small dashboard text, scrolling and impaired network conditions. Tighten or change the transport based on those results. The JSON can be regenerated after changes; it is a snapshot, not a continuous monitor.
